# k3d/K3s 중심 학습 문서 설계

2026-11-14 사용자가 승인한 24장 목차와 집필 방식의 기록이다.

## 목적

현재 플랫폼을 이해하기 위해 k3d/K3s와 Kubernetes를 먼저 학습한다. 설정값을
암기하는 대신 프로세스, 실행 환경, 제어 과정, 네트워크, 저장소의 관계를 설명한다.
독자는 Python 코드를 읽을 수 있지만 Kubernetes 구성 요소에는 익숙하지 않다고 가정한다.

## 선택한 접근

기존 도구별 문서를 보충하는 방식과 개념 순서로 다시 구성하는 방식을 비교했다.
후자를 승인받았다. `docs/study/chapters/`의 24장을 주 학습 경로로 만들고,
기존 도구별 경로는 설정 참고 자료로 유지해 외부 링크와 기존 내용을 보존한다.

## 구조와 집필 기준

- 1–6장: 실행 환경, Colima/Docker, Kubernetes/K3s/k3d, 노드와 제어 구성 요소.
- 7–10장: 선언부터 실행까지, Pod 수명, 컨트롤러, 이미지와 자원.
- 11–14장: 네트워크, Service/DNS/Ingress, 저장소, 설정·신원·권한.
- 15–17장: 출력 해석, Helm과 설정 적용, 복구와 단일 노드의 한계.
- 18–21장: Airflow 개념, 두 작업 DAG, worker 실행, 배포·로그·동시성·대기.
- 22–24장: 데이터 저장 계층, 처리 엔진, 전체 경로 복습.
- 각 장: 필요성 → 동작 원리 → 프로젝트 파일 → 조회 실습/예상 결과 → 확인 문제/해설.
- 낯선 용어를 처음 나올 때 정의하고, 명령어는 인자와 출력의 의미를 설명한다.
- README에 전체 목차와 학습 구간별 통과 기준을 제공한다.
- 과거 실행 기록, 현재 저장소 선언, 설명용 예시를 구분한다.

## 범위와 검증

문서만 수정한다. 클러스터 변경, 업무 DAG 실행, Secret 출력, 배포·push는 하지 않는다.
본문 실습은 조회 중심이고, DAG 실행은 별도 선택 실습으로 표시한다.
기존 미커밋 파일을 보존한다. 링크, 목차, 장별 구성, 코드 블록 문법을 오프라인으로
검증하고 공식 문서 및 실제 manifest와 대조한다. 실시간 상태를 새로 검증했다고 쓰지 않는다.
